Session 5: We added a CLI job progress bar to the dashboard — a thin blue bar that appears above the repo controls when a refresh is running and advances as each repo completes. The bar is driven by a `public/progress.json` file that `cli.js` writes during the run, a `GET /progress` endpoint in `server.js`, and a `pollProgress()` poller in `app.js`. The first bug we hit was that the bar showed 0% the entire time and then jumped to 100% at the end. The root cause was that both POST refresh handlers used `await runCLI(...)` before sending the HTTP response, which blocked Node's event loop for the entire duration of the CLI job. Every `/progress` poll queued up and could not be answered until the job finished. The fix was to send `202 Accepted` immediately and fire `runCLI()` as a background promise, freeing the event loop to service polling requests in real time. The lesson: in a single-threaded Node HTTP server, any long-running `await` inside a request handler blocks all other requests — fire-and-forget background work and respond to the client first.
