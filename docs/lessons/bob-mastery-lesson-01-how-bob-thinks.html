How Bob Thinks: The Core Mental Model

Before you can use Bob well, you need an accurate mental model of what it actually is. Not "AI chatbot." Not "code autocomplete." Something more specific.

Section 1 of 4

Bob is an agent, not a chatbot

A chatbot takes text in and returns text out. Bob takes a request, decides what to do, and then does it — calling tools, reading files, running commands, and producing side effects in your actual project. That's the difference.

IBM describes Bob as an "AI SDLC partner." The SDLC framing is deliberate: Bob is designed to participate in every phase of software development — planning, writing, reviewing, debugging, and documenting — not just generate code snippets on demand.

Practically, this means Bob is stateful during a conversation. It builds up context about your project as you work, uses that context to make decisions, and executes those decisions through a set of tools. You're the approver in that loop.

PM Insight

When you're talking to stakeholders or writing positioning copy, the key differentiator isn't "AI coding assistant" (every tool claims that). It's agentic execution — Bob acts on your codebase with tools, not just advises. That's the line between a copilot and a partner.

Section 2 of 4

The context window: Bob's working memory

Bob runs on a large language model with a 270,000-token context window. Think of it as working memory: everything Bob "knows" during a conversation must fit inside it. When the window fills up, either older content falls off or you start a new conversation.

The context window isn't just your chat messages. It has several cost-contributing layers that always fill first:

Every prompt re-sends the entire active context. So a one-line follow-up message in a long thread costs almost as much as re-asking the full original question. This is why context management is a core practice, not a nice-to-have.

Key mechanic: context poisoning

If a conversation has drifted — Bob made incorrect assumptions or bad edits earlier — those errors are now baked into the context. Every subsequent response is influenced by them. The fix isn't to argue with Bob; it's to start a new conversation (clearing the bad context) and be more precise the second time.

PM Insight

Context window = cost driver. Longer conversations, more file reads, and bigger rules files all increase Bobcoin spend per prompt. This is a direct product design tradeoff: capability vs. cost. As PM, you'll be asked about this when teams start hitting budget limits.

The tool execution loop

Bob decides what to do with your request, then executes it through a sequence of tool calls. For each step, it tells you what tool it wants to run and why, you approve (or it auto-approves if you've enabled that), and then the tool runs.

Here's what that looks like in practice when you ask Bob to "add a unit test for the login function":

Bob tool execution trace — "Add a unit test for login"
Your prompt
Add a unit test for the login function.

Step 1 — Read

glob("**/auth/**") → finds auth/login.ts, auth/login.test.ts
read_file("auth/login.ts") → reads the function signature and logic

Step 2 — Read

read_file("auth/login.test.ts") → reads existing test patterns to match style

Step 3 — Write (requires your approval)

apply_diff("auth/login.test.ts") → inserts new test case

Step 4 — Execute (requires your approval)

execute_command("npm test auth/login.test.ts") → verifies the test passes

Notice that Bob didn't just generate code — it explored the codebase first (read tools), matched existing patterns, made the change (write tool), and verified it worked (execute tool). That's the agentic loop in action.

Important

The mode you're in determines which tools Bob can use. In Ask mode, Bob can't call write or execute tools at all — it's read-only. In Agent mode, all tools are available. This is a fundamental safety constraint, not just a UX convention. Lesson 02 goes deep on this.

Section 4 of 4

Bobcoins: how usage translates to cost

Bob doesn't bill you in raw tokens because different models have different token costs — using Claude costs differently than using GPT-4o. Bobcoins are a unified billing metric that normalizes across all underlying models so you get predictable cost accounting regardless of which model is active.

You don't set or track tokens. You set Bobcoin budgets. The conversion happens automatically.

Two key cost levers you control as a user:

  • 1. Conversation length. Every message re-sends the full context. Long conversations multiply cost quickly. Start new conversations for new tasks.
  • 2. File reads. Asking Bob to read large files or whole directories loads them into context, which persists for the entire conversation. Be surgical about what you ask Bob to read.
PM Insight

Enterprise customers get a shared Bobcoin pool distributed from a centralized budget. This makes Bob spend a team-level management problem, not just an individual setting. The Bobalytics dashboard (Lesson 06) shows team-level usage but deliberately hides individual user data — a deliberate product privacy choice you should understand cold.
